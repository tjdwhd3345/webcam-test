# 카메라 리팩터링 검증 페이지

AS-IS `useCameraStream`과 TO-BE production 카메라 정책을 같은 브라우저 조건에서 비교하는 React/Vite 테스트벤치입니다. 한 번에 한 패널만 mount하여 두 구현이 동시에 카메라 스트림을 소유하지 않도록 구성했습니다.

## HTTPS로 실행

브라우저 카메라 API는 secure context가 필요합니다. 저장소에 준비된 로컬 인증서를 사용해 Vite HTTPS 서버를 실행합니다.

```bash
npm install
npm run dev
```

터미널에 표시된 `https://` 주소를 열고 로컬 인증서를 신뢰한 뒤 테스트합니다. 상단 runtime status에서 `isSecureContext`와 `getUserMedia`가 모두 `true`인지 먼저 확인합니다.

## 테스트 모드

- `AS-IS`: 기존 `useCameraStream`의 후면 카메라 선별, 해상도 fallback, 선택 장치 재생을 확인합니다.
- `TO-BE`: `useIdcardCameraStream`, `IdcardCameraPolicy`, `MediaDevicesCameraGateway`를 연결해 production 준비 결과, 장치별 정책 결정, strict-mobile 제약, 스트림 검증을 확인합니다.

TO-BE 이식 기준은 2026-10-22에 원격 `main`에서 확인한 `ais-kyc.fe`의 커밋 `2b66f8281f70b738412b41c082437b97677397ae`입니다. Sentry 연동은 이 테스트 앱 범위에서 제외했으며, import alias와 테스트는 이 프로젝트의 `@tobe` 경로 및 Vitest 환경에 맞췄습니다. 이식한 카메라 정책에는 아래 다국어 라벨 필터를 추가했습니다.

ultra/wide/광각/망원 라벨 필터는 기존 한국어·영어 외에 일본어(`広角`, `望遠`), 중국어 간체(`广角`, `长焦`), 중국어 번체(`廣角`, `望遠`), 베트남어(`rộng`, `chụp xa`)도 인식합니다. 광각 키워드는 초광각·듀얼 광각 라벨도 포함하며, 일반 듀얼·트리플 라벨은 키워드만으로 제외하지 않습니다. 베트남어는 대소문자를 구분하지 않고 단어 사이의 연속 공백을 허용합니다.

프랑스어·태국어·러시아어·인도네시아어·벵골어 라벨도 다음 키워드로 인식합니다. 대소문자를 구분하지 않고, 구절 사이의 연속 공백을 허용합니다. 러시아어는 아래 어간으로 굴절된 라벨도 인식합니다.

| 언어 | 광각·초광각 | 망원 | Triple 우선순위 판별 |
|---|---|---|---|
| 프랑스어 | `grand angle` | `longue focale` | `triple` |
| 태국어 | `ไวด์`, `มุมกว้าง` | `ภาพระยะไกล` | `สามกล้อง` |
| 러시아어 | `широкоугольн` | `телеобъектив` | `тройн` |
| 인도네시아어 | `lebar` | `tele` (`Telefoto` 포함) | `tiga kamera` |
| 벵골어 | `ওয়াইড` | `টেলিফটো` | `ট্রিপল` |

Triple은 모든 지원 언어에서 제외 키워드가 아니므로 zoom 정보가 없어도 라벨만으로 제외하지 않습니다. 후면으로 확인되고 zoom 최솟값·최댓값이 모두 유한한 숫자이며 범위에 1을 포함하면 기존 adaptive 우선순위와 `zoom.min < 1` 제외의 예외를 적용합니다. 이 조건을 충족하지 않으면 일반 장치와 같은 방향·zoom 조건으로 판단합니다. 허용 후보 실행에 실패하면 다음 후보를 순차적으로 시도합니다.

## 수동 검증 순서

1. 상단에서 `AS-IS`를 선택하고 `카메라 권한` → `후면 카메라 실행`을 실행합니다.
2. 영상, 선택 장치, 해상도, settings/capabilities를 기록하고 `정지`합니다.
3. `TO-BE`로 전환합니다. 전환 직후 AS-IS 카메라 표시등이 꺼졌는지 확인합니다.
4. 모바일 브라우저에서는 기본 활성화된 `모바일 후면 카메라 강제`를 유지합니다. 데스크톱에서 모바일 조건을 재현할 때는 직접 체크합니다. strict 모드는 선별된 장치 ID를 `exact`로 고정하고 후면 방향은 `ideal`로 요청한 뒤 열린 스트림을 검증합니다.
5. `후면 카메라 실행` 후 선택 사유, 방향, 해상도 시도와 `valid` 여부를 기록합니다. 확인된 후면 장치는 `verified_environment`가 표시됩니다. 방향 미상 장치는 strict 모드에서도 `unknown_compatibility` 후보가 될 수 있으며, 이때 facing 제약은 `ideal`입니다. 데스크톱은 전면/방향 미상 및 기본 장치(`default_compatibility`)도 호환 경로로 허용합니다. `preferred` 해상도가 지원되지 않으면 `fallback`으로 성공할 수 있습니다.
6. `카메라 목록 조회`는 권한 상태가 `prompt`이면 먼저 카메라 권한을 요청할 수 있습니다. 조회 후 일반 후면 카메라는 통과하고 ultra/wide 계열은 `excluded_by_label` 또는 `excluded_by_zoom_min`으로 제외되는지 확인합니다.
7. 장치를 선택하고 `선택 장치 직접 재생 (진단)`을 실행합니다. 직접 재생 직전에 목록을 다시 확인해 같은 비어 있지 않은 장치 ID만 `exact`로 열며, 장치가 사라졌다는 안내가 나오면 목록을 다시 조회합니다. 직접 재생 검증과 실제 settings/capabilities를 확인합니다.
8. 다른 장치를 직접 재생하거나 모드를 전환했을 때 이전 카메라 표시등이 꺼지는지 확인합니다.
9. 브라우저가 `video.play()`를 거절하면 현재 자동 스트림 또는 직접 재생 스트림에 해당하는 오류만 화면에 표시되는지 확인합니다.

권한 요청과 TO-BE 장치 조회는 현재 재생을 정지한 뒤 실행합니다. TO-BE 목록 조회가 권한 bootstrap 스트림을 열면 장치 열거 전에 즉시 정리합니다. 정지/모드 전환으로 취소한 명시적 실행이 브라우저 응답을 기다리는 중이면, 다음 명시적 실행은 이전 결과 정리가 끝날 때까지 대기합니다. 복사된 hook 내부의 초기 장치 조회 및 자동 복구는 원본 동작을 유지합니다. 복구가 스트림을 교체하면 이전 준비 결과는 숨기며, 진행 상태와 hook 오류를 표시합니다.
